# 채널 백엔드 PRD 인터뷰지

v0.6 · 채널 백엔드 인터뷰 양식

이 문서는 여러 프로젝트에서 재사용할 질문 양식이다. 적용 업무에서 확정한 답변과 근거는 해당 프로젝트의 Confluence PRD에 기록한다. 질문이나 예시를 바꿀 때는 PR에 변경 이유와 영향받는 질문 ID를 남긴다.

마스터 PRD에서 기능 하나를 고르고, 관련 문서로 확인할 수 있는 답을 먼저 채운다. **공통 질문 → 업무별 질문 → 해당하는 조건부 질문** 순서로 살펴보고, 구현이나 검수 결과가 달라지는 미결 사항을 인터뷰에서 확인한다. 업무별 질문에 연결된 공통 질문 번호는 관련 내용을 찾을 때 사용한다.

채널 백엔드 인터뷰에서 확정할 범위는 **API 계약, 서버의 업무 판단과 상태 전이, DB·계정계 연계, 서버 검수 기준**이다. 프론트 담당자와는 API 호출 시점, 요청·응답, 오류·상태 코드, 기존 호출자 호환성을 합의한다. 화면 구성·이동 방식·컴포넌트·안내 문구는 디자인 또는 채널 프론트엔드 PRD에 기록한다.

| 인터뷰 정보 | 기록 |
|---|---|
| 대상 기능 및 요구사항 ID | [기능명 / 마스터 요구사항 ID] |
| 업무 및 처리 단계 | [카드·수신·여신 / 조회·자격 판단·신청 또는 실행·후처리 중 해당 단계] |
| 마스터 PRD 기준 | [Confluence 링크 / 참조 버전] |
| 관련 자료 | [호출 시나리오 또는 프론트 PRD의 API 계약·계정계 PRD·전문 명세·테스트 중 해당 자료] |
| 인터뷰 참석자 및 날짜 | [이름 / 역할 / 날짜] |

## 4. 답변을 PRD로 넘길 때

| 질문 ID | 확인된 답 또는 미결 사항 | 결정 담당·확인 시점 | 근거 또는 문서 버전 | 연결할 PRD 항목·검수 ID |
|---|---|---|---|---|
| [Qxx 또는 CARD·DEP·LOAN 질문 ID] | [답변 / 미정] | [담당 / 필요한 시점] | [결정 기록, 계약 또는 확인한 자료] | [항목 / 검수 케이스] |

운영 소스에서 확인한 내용과 새 제품에 적용할 결정을 구분해 기록한다. 프론트·계정계 등 여러 팀의 동작에 영향을 주는 미결 사항은 마스터 PRD의 공통 결정에 연결한다. 예외 정책이 미정이면 어느 응답·저장 결과·검수 케이스가 미정인지 함께 적는다.

근거에는 프론트의 화면·분기, 서버 코드, 공식 인터페이스 계약 또는 실행 결과 중 무엇을 확인했는지 적는다. 화면에서 차단하거나 안내하는 동작만 확인된 경우 서버의 최종 판단, 원인 코드, 데이터 출처는 각각 확인할 사람과 자료를 남긴다.

## 예시 답변 읽는 법

아래 답변의 정책, 필드명, 응답 코드, 금액은 **작성 방법을 보여주기 위한 가상 결정**이다. 실제 PRD에서는 담당자가 합의한 답과 결정 근거를 기록하고, 적용 조건과 반환값을 검수 케이스에 옮긴다.

## 적용 예시 · 제휴신용카드 홈 조회

가상의 상품 홈은 배너와 상품 목록의 노출 여부를 응답에 포함한다. 정상 빈 결과와 일부 조회 실패의 반환값을 아래처럼 합의했다고 가정한다.

| 질문 | 예시 답변 | PRD 반영 | 검수 케이스 |
|---|---|---|---|
| Q04·CARD-01 · 배너 데이터 출처 | 채널 DB에서 노출 기간에 해당하는 배너를 관리자가 정한 순서로 가져온다. | 데이터 출처, 노출 기간 조건, 정렬 기준 | 노출 기간 밖의 표본과 순서가 다른 표본을 넣어 반환 대상과 순서를 확인한다. |
| Q05·CARD-01 · 정상 0건과 배너 조회 실패 | 배너 조회 성공·0건이면 `hasBanners = false`과 빈 배열을 반환한다. 배너만 조회에 실패하고 나머지가 성공하면 같은 빈 배열과 `warnings`의 `BANNER_LOOKUP_FAILED`를 함께 반환한다. | 빈 결과와 부분 실패의 응답 예시 | 0건일 때 경고가 없고, 배너 타임아웃일 때 경고와 나머지 목록이 함께 반환되는지 확인한다. |

## 적용 예시 · 신용대출 실행 결과 확인

실행 요청의 처리 결과를 바로 알 수 없는 가상 시나리오다. 실제 제품에서는 계약을 확인해 실행 API, 상태 코드, 조회 경로와 재처리 정책을 결정한다.

| 질문 | 예시 답변 | PRD 반영 | 검수 케이스 |
|---|---|---|---|
| LOAN-05·Q11 · 실행 요청 타임아웃 | 실행 요청 후 타임아웃이 나면 채널은 `PENDING_CONFIRMATION`으로 응답한다. 실행 요청 ID로 계정계 결과를 조회해 실행 완료 또는 실패가 확인되면 상태를 갱신한다. | 계정계 처리 결과의 확인 방법, 채널 상태 전이 | 계정계에서 실행은 완료됐지만 최초 응답만 타임아웃된 경우, 결과 확인 전에는 대기, 확인 후에는 완료를 반환한다. |
| LOAN-05·Q12 · 같은 실행 요청 재제출 | 같은 실행 요청 ID로 다시 제출하면 기존 처리 상태를 반환한다. 최초 요청의 결과 확인이 진행 중인 동안 같은 요청에 대한 실행 전문은 한 번만 전송한다. | 동일 요청의 판단 기준, 재제출 응답과 외부 호출 횟수 | 동일 ID로 동시에 두 번 요청했을 때 한 번만 실행되고, 두 응답이 같은 실행 건을 참조하는지 확인한다. |
